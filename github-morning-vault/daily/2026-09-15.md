## 今日新增项目

### 1. blancmathis/voicecode-mcp
- GitHub：https://github.com/blancmathis/voicecode-mcp
- 一句话用途：让编码 Agent 在任务关键节点发起实时语音对话，拿回转录后继续执行。
- 为什么值得看：它不是普通语音输入，而是把“澄清需求、Bug 复现、架构决策、验收反馈”做成 Agent loop 内的语音检查点；支持本地完成队列、转录恢复和多 Session 排队。
- 适合怎么用：用于 Codex 在需求不清、需要人做选择或最终验收时主动升级到语音；与现有 mcp-listen/voicesmith-mcp 区分，重点看“对话式对齐”而不是单纯 STT/TTS。
- 本地部署/测试成本：中；需要 uv/本地 MCP 配置，当前 provider 依赖 HiCharlie 与 API Key，语音通话本身不是完全离线。
- 当前状态：`REVIEW`
- 下一步建议：先审查 provider 依赖、隐私边界和 Codex transcript 回传；用一次“需求澄清→继续实现”的短任务验证实际收益。
- 收藏库联动标记：**已收藏 / 值得跟进**

### 2. WANGLEVY9/VidForge
- GitHub：https://github.com/WANGLEVY9/VidForge
- 一句话用途：面向商品/产品叙事的可自托管多 Agent AI 视频生产流水线。
- 为什么值得看：它把素材理解、品牌知识、脚本规划、视频生成、质量反馈、媒体合成和成本追踪放进一个可观测工作区，而不是一次性生成。
- 适合怎么用：作为 videoclaw2 之上的“知识与质量层”候选；先用本地/Mock Provider 测试素材理解、RAG 脚本和 QC，再接 ComfyUI、FFmpeg、TTS 或云端视频模型。
- 本地部署/测试成本：中高；可自托管，纯探索可不接付费凭据，但真实文本/视觉/视频/TTS 生成需要对应 provider；需要 Docker/数据库/模型服务等按 README 配置。
- 当前状态：`TRY`
- 下一步建议：用一件实际产品做 30 秒短视频，记录“素材理解→脚本→生成→QC→合成”每阶段输入输出和失败点，验证是否比现有多工具串联更稳定。
- 收藏库联动标记：**已收藏 / 值得跟进**

### 3. TuanLe-bk18/local-knowledge-mcp
- GitHub：https://github.com/TuanLe-bk18/local-knowledge-mcp
- 一句话用途：以默认拒绝、只读优先的方式，让 Agent 安全浏览本地知识目录并按需做受控整理。
- 为什么值得看：它把本地知识管理的关键问题放在安全模型上：root allowlist、路径别名、禁止越界、隐藏文件/Secrets 保护，以及 Analyze→Approve→Apply 的显式变更流程。
- 适合怎么用：作为 Cairn/gno/MarkItDown 之前的“文件治理边界层”，先管理资料副本，再把整理后的目录交给检索与文档预处理链路。
- 本地部署/测试成本：低～中；普通 Python 包即可运行，无需云端；测试重点是目录授权、移动规则、审计日志和 Windows 兼容性。
- 当前状态：`TRY`
- 下一步建议：在测试资料目录中验证“扫描→生成整理计划→人工批准→移动→审计”完整闭环，禁止直接连接主资料盘。
- 收藏库联动标记：**已收藏 / 值得跟进**

### 4. hannasdev/mcp-document-reader
- GitHub：https://github.com/hannasdev/mcp-document-reader
- 一句话用途：给 Agent 提供分页读取、全文搜索和按页导航的大型 PDF 阅读 MCP。
- 为什么值得看：它针对的是长文档上下文浪费，不要求每次从第一页重新塞入模型；与 markitdown/doc7 的“文档转格式”互补，更偏阅读控制和定位。
- 适合怎么用：作为论文、标准、研究报告的轻量阅读入口；先让 Codex 搜索关键词和页码，再决定是否交给 MarkItDown/doc7 做完整抽取。
- 本地部署/测试成本：低；Node.js + npm，仓库体量小，适合快速验证，但需要关注大 PDF 的解析稳定性和项目维护活跃度。
- 当前状态：`REVIEW`
- 下一步建议：用一个 300 页左右的 PDF 测试关键词定位、分页读取、重复读取 Token 和表格/公式处理效果，再决定是否纳入研究工作台。
- 收藏库联动标记：**已收藏 / 值得跟进**

## 今日判断

今天最值得先测的是 `TuanLe-bk18/local-knowledge-mcp` 与 `WANGLEVY9/VidForge`：前者补“安全文件治理边界”，后者补“知识驱动的视频生产与质量层”。`voicecode-mcp` 的概念有价值，但当前 provider 依赖云端语音服务，先做架构审查；`mcp-document-reader` 适合做轻量 PDF 阅读补充，不宜直接替代现有文档预处理链路。
