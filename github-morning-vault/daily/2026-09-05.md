## 1. ChromeDevTools/chrome-devtools-mcp
- GitHub: https://github.com/ChromeDevTools/chrome-devtools-mcp
- 一句话用途：把 Chrome DevTools 直接暴露给 Codex 等 coding agent，用于真实浏览器调试、性能分析和自动化验证。
- 为什么值得看：这是 Chrome DevTools 官方团队维护的 MCP；支持页面检查、网络/控制台调试、性能 trace 等，比单纯让 Agent 操作 DOM 更适合开发和 QA。
- 适合怎么用：Codex 完成 Web 项目修改后，自动打开本地页面 → 检查 console/network → 跑性能 trace → 根据证据修复 → 再验证，形成 coding-to-browser 闭环。
- 本地部署/测试成本：低～中。Node/npm + Chrome；Codex 可直接 `codex mcp add chrome-devtools -- npx chrome-devtools-mcp@latest`。Windows 11 官方文档已有专门配置，但应留意启动超时和 Chrome 路径。
- 当前状态：`TRY`
- 下一步建议：在独立 Web demo 中验证“Codex 修改代码 → Chrome DevTools MCP 检查 → 自动修复 → 二次验证”完整闭环；同时关闭非必要 usage statistics。
- 收藏库联动：**已收藏 / 值得跟进**

## 2. sickn33/agentic-awesome-skills
- GitHub: https://github.com/sickn33/agentic-awesome-skills
- 一句话用途：本地 Agent Skill 控制平面和大型技能目录，让 Codex 根据真实项目自动挑选、组合并验证 Skill stack。
- 为什么值得看：AAS Core 当前提供 2,100+ agentic skills，并把“Agent 自己选 Skill”与“真正安装/变更”分开；本地 MCP 为只读、可离线，选择结果可保存为可审查的 `aas-stack.json`。
- 适合怎么用：让 Codex 先分析项目，再搜索完整 Skill catalog，选择最小非重复技能组合；用户审核后才进入 validate/plan/apply。适合解决 Skill 越积越多后的发现、重复和治理问题。
- 本地部署/测试成本：中。需要配置 AAS Core/CLI 和本地 MCP，但不要求模型凭据；当前 apply/recovery 仍偏 preview，应先停在 plan review。
- 当前状态：`TRY`
- 下一步建议：拿一个真实 Codex 项目，让 AAS 自动生成一个 3～6 个 Skill 的 `aas-stack.json`；与现有 `local-skills-mcp` 比较“自建 Skill 管理”与“大目录自动选型”的差异。
- 收藏库联动：**已收藏 / 值得跟进**

## 3. nexu-io/open-design
- GitHub: https://github.com/nexu-io/open-design
- 一句话用途：local-first 的 Agent 设计工作台，让 Codex 等 coding agent 生成和迭代原型、网页、Dashboard、Slides、图像与视频并导出真实文件。
- 为什么值得看：它不是单一图片生成器，而是尝试把 coding agent 变成设计引擎；支持 Codex/Cursor/Claude Code 等 20+ CLI，并强调 HTML/PDF/PPTX/MP4 等真实文件输出。
- 适合怎么用：让 Codex 从需求直接生成交互原型、汇报页或演示资产，再人工调整；可作为“代码 Agent → 视觉交付物”的桥梁。
- 本地部署/测试成本：中。桌面/local-first 路线降低数据外发压力，但项目较新，实际稳定性、Windows 体验和多格式导出质量需要验证。
- 当前状态：`REVIEW`
- 下一步建议：暂不接主工作流；先用一个 Dashboard 或 PPT 页面任务测试从 Prompt → 可编辑源文件 → PDF/PPTX 导出的质量，再决定是否升为 TRY。
- 收藏库联动：**已收藏 / 值得跟进**

## 4. ripunjay-kashyap/audio-sonic-mcp
- GitHub: https://github.com/ripunjay-kashyap/audio-sonic-mcp
- 一句话用途：完全本地的音频分析 MCP，把歌曲/音频转成 BPM、调性变化、结构、vocal presence、transient、stereo width 和 CLAP 风格向量等可供 Agent 使用的“声音特征”。
- 为什么值得看：当前收藏库的声音项目多集中在 STT/TTS/RVC/生成/REAPER 控制，而它补的是“听懂音乐制作特征”的分析层；使用 Demucs、librosa、CLAP，可 CUDA 加速并支持 CPU 降级。
- 适合怎么用：在 RVC/REAPER 工作流前后自动分析原曲与成品，比较 BPM、调性段落、频谱/瞬态/立体声和风格特征，为 Codex/Reaper-MCP 提供客观 QC 数据。
- 本地部署/测试成本：中～高。完整能力涉及 Demucs/CLAP 和音频 ML 依赖；有 GPU 更合适，但支持轻量 CPU/HPSS 降级。
- 当前状态：`REVIEW`
- 下一步建议：用同一首歌的原曲、RVC 人声、最终混音三个版本跑分析，判断指标是否真的能帮助定位“高音发紧、电子感、混音空间”等问题；有效再升 TRY。
- 收藏库联动：**已收藏 / 值得跟进**

## 今日可执行 Idea

### P0 — Codex Browser QA Loop
`Codex + Chrome DevTools MCP + Web 项目`

让 Codex 不只负责写代码，还负责基于真实浏览器证据验证结果：修改 → 打开页面 → console/network/performance 检查 → 修复 → 回归验证。适合后续所有 Web/交互项目形成统一验收 Skill。

### P1 — Agent Skill Governance Layer
`AAS Core + local-skills-mcp + Codex`

把现有“自己写 Skill”进一步升级成 Skill 治理体系：私有高价值 Skill 继续由 local-skills-mcp 管理；通用能力由 AAS catalog 搜索；项目级 `aas-stack.json` 记录最终启用组合，避免 Skill 无限制堆积。

### P1 — Audio QC Intelligence Layer
`audio-sonic-mcp + RVC + Reaper-MCP`

在声音生成与 REAPER 后期之间增加客观分析层：原曲/转换人声/最终混音自动生成 sonic signature，Codex 根据差异决定需要人工试听的重点片段和后期处理方向。
