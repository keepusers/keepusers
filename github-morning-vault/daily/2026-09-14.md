## 今日新增项目

### 1. brunogcar/agent
- GitHub：https://github.com/brunogcar/agent
- 一句话用途：基于 MCP + LangGraph + LM Studio 的本地 Agent 执行平台，内置多角色模型、工作流、记忆、浏览器、代码与报告工具。
- 为什么值得看：它把本地模型、工具调用、持久记忆、TDD 自动编码、定时任务和可选云端升级整合成一个完整运行时，不只是单一 MCP Server。
- 适合怎么用：作为 LocalAI/LocalAGI 之外的“本地 Agent Runtime 对照组”；重点测试 research、understand、autocode 三类工作流，再接入 Codex 做任务分派或结果审查。
- 本地部署/测试成本：中高；Python 3.11+、Node 18+、LM Studio、Playwright、ChromaDB/SearXNG，Windows 生成 PDF 还需 GTK3 Runtime。
- 当前状态：`TRY`
- 下一步建议：用一个小型代码仓库跑通 `understand → autocode → pytest → report`，记录显存、耗时、返工和失败恢复能力。
- 收藏库联动标记：**已收藏 / 值得跟进**

### 2. wewaa/videoclaw2
- GitHub：https://github.com/wewaa/videoclaw2
- 一句话用途：面向 AI 视频生产的本地/云混合 Agent OS，用 YAML DAG 编排脚本、分镜、生成、配音、合成、渲染和发布。
- 为什么值得看：它把视频工作流从“多个工具串联”提升到“可版本控制的流水线”，具备并行执行、失败恢复、成本追踪、质量审查和本地模型适配。
- 适合怎么用：作为现有 ComfyUI/OpenChatCut/ffmpeg-skill 之上的流程编排层；先用 mock/local 模型跑通 YAML，再接入真实视频、TTS 和 FFmpeg。
- 本地部署/测试成本：中；Python 3.12+，可直接 pip 安装或 Docker 启动；真实生成仍需模型/API，纯本地模式取决于适配器。
- 当前状态：`TRY`
- 下一步建议：写一个 30 秒短视频 YAML，固定脚本、分镜、配音、合成和交付 QA 五个阶段，验证断点恢复和预算门禁。
- 收藏库联动标记：**已收藏 / 值得跟进**

### 3. LudwigKienle/ai-video-production-editor
- GitHub：https://github.com/LudwigKienle/ai-video-production-editor
- 一句话用途：本地优先的 AI 影视制作工作台，覆盖脚本、导演、分镜、拍摄、剪辑、调色、3D 预演和导出。
- 为什么值得看：它把 AI 视频生成、研究图谱、素材库、时间线、色彩和插件系统放进一个项目目录，适合观察“生产工作台”能否替代多工具跳转。
- 适合怎么用：先作为桌面工作台评估，不急于接管现有 RVC/REAPER/ComfyUI 主流程；重点看项目文件组织、分镜连续性检查、离线自动剪辑和插件机制。
- 本地部署/测试成本：中；可直接使用 Windows EXE，也可 Node.js 20.19+/22.12+ 源码运行；部分模型与服务需要自有 API Key。
- 当前状态：`REVIEW`
- 下一步建议：用一个短视频项目测试“脚本→分镜→素材库→剪辑→导出”完整链路，重点记录本地数据可移植性和生成结果可控性。
- 收藏库联动标记：**已收藏 / 值得跟进**

### 4. JuanMaParraU/a2a-mcp-langgraph-agent-local
- GitHub：https://github.com/JuanMaParraU/a2a-mcp-langgraph-agent-local
- 一句话用途：用 Ollama + LangGraph + MCP + A2A 搭建完全本地的多 Agent 协作示例。
- 为什么值得看：它把 MCP 的工具调用与 A2A 的 Agent 间通信放到同一套本地架构中，适合研究跨 Agent 任务转交、角色分工和消息协议。
- 适合怎么用：作为“Codex 主 Agent → 本地研究 Agent → 本地执行 Agent”最小协议实验，不直接用于生产。
- 本地部署/测试成本：中；需要 Python 环境、Ollama 和多个本地模型，重点成本在模型内存与多 Agent 调试。
- 当前状态：`REVIEW`
- 下一步建议：只跑两个 Agent：一个负责计划，一个负责执行；记录消息格式、上下文重复量和失败重试机制，再决定是否与 agent-rack/Concord 合并研究。
- 收藏库联动标记：**已收藏 / 值得跟进**

## 今日判断

今日最值得实际测试的是 `brunogcar/agent` 与 `wewaa/videoclaw2`：前者补“本地 Agent Runtime”，后者补“视频流水线编排”。两者都比继续增加一个普通 MCP 工具更有结构性价值。

## 今日 Idea

1. **Local Agent Runtime Benchmark**（P0）
   - 来源：brunogcar/agent + LocalAI + LocalAGI + Codex
   - 方向：统一测试本地模型调用、工具执行、记忆、工作流恢复、代码任务成功率与 Token/显存成本。

2. **YAML-Driven AI Video Factory**（P0）
   - 来源：wewaa/videoclaw2 + ComfyUI + OpenChatCut + ffmpeg-skill + Reaper-MCP
   - 方向：用版本化 YAML 描述脚本、镜头、配音、音效、剪辑、QC 和交付，形成可重跑的视频生产流水线。

3. **Local Multi-Agent Protocol Lab**（P1）
   - 来源：a2a-mcp-langgraph-agent-local + agent-rack + Concord
   - 方向：比较 MCP 子 Agent、A2A 消息、共享记忆和任务交接的成本，选择长期统一协议。
