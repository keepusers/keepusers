### kdpa-llc/local-skills-mcp — TRY
- 链接：https://github.com/kdpa-llc/local-skills-mcp
- 一句话用途：把本地 SKILL.md 技能库通过 MCP 提供给多个 Agent，并按需懒加载完整技能内容。
- 为什么值得看：直接对应“技能复用 + 降低上下文/Token 消耗”，而且技能可以跨 Agent 共用。
- 适合怎么用：把常用的 GitHub 调研、软件安装、文档预处理、项目复盘等流程沉淀为本地技能。
- 部署/测试成本：低～中；先建 3～5 个小技能验证 lazy loading 和 MCP 兼容性。
- 当前状态：TRY
- 下一步建议：优先做一个 GitHub 项目评估 SKILL.md，再测 Codex/MCP 客户端是否能按需读取。
- 收藏库联动：已收藏

### halilibrahimyesirci/nexus-local-rag-mcp — REVIEW
- 链接：https://github.com/halilibrahimyesirci/nexus-local-rag-mcp
- 一句话用途：无 API Key、无云端、无 Docker 的 PDF/Markdown/TXT 本地关键词+语义检索 MCP。
- 为什么值得看：比完整知识平台更轻，CPU 本地 embedding + SQLite 适合小型项目知识库。
- 适合怎么用：作为单个 Codex 项目的 sidecar 知识库，和 gno 做“轻量 vs 完整”比较。
- 部署/测试成本：低～中；首次下载 embedding 模型，之后可离线运行。
- 当前状态：REVIEW
- 下一步建议：暂不和 gno 重复部署；先用同一组文档比较检索准确率、启动成本和资源占用。
- 收藏库联动：已收藏

### decibri/mcp-listen — TRY
- 链接：https://github.com/decibri/mcp-listen
- 一句话用途：给 MCP Agent 增加本地麦克风录音、whisper.cpp 转写和本地语音查询能力。
- 为什么值得看：支持 Windows x64，预编译音频捕获、VAD 在本机运行，不需要 FFmpeg/SoX；适合做低成本语音输入层。
- 适合怎么用：和现有 TTS/Voice 项目组合，形成“说话→转写→Agent→语音反馈”的本地双向链路。
- 部署/测试成本：低～中；npx 可启动，voice_query 需要 Whisper GGML 模型。
- 当前状态：TRY
- 下一步建议：先测试 Windows 麦克风捕获和中文 Whisper 模型，再决定是否替代更重的 VoiceSmith 方案中的输入部分。
- 收藏库联动：已收藏
