### 1. Ericwong5021/better-codex

- GitHub: https://github.com/Ericwong5021/better-codex
- 一句话用途：在 Codex Desktop 内加入 local-first 任务看板和 Agent 执行系统。
- 为什么值得看：不是再增加一个独立 Agent，而是补 Codex Desktop 的任务组织、分派和运行状态层；本地 SQLite 为权威数据源，runtime 只监听 127.0.0.1，并明确支持 Windows x64 与 macOS。仓库 2026-09-09 仍有 push，当前约 40 Stars，维护活跃度比规模更值得关注。
- 适合怎么用：把复杂项目拆成可追踪任务，让 Codex 负责执行，再与 AgentsView 的 Session/Token 观测、现有 Harness Bake-off 结合。
- 本地部署/测试成本：**低～中**。Windows 有正式支持，但它通过 Codex Desktop 的本地页面/CDP 能力做集成，Codex 更新可能带来兼容性变化；应先在测试项目验证 doctor/eject/uninstall 和升级恢复。
- 当前状态：**TRY**
- 下一步建议：建立一个 5～8 个任务的小型真实项目，对比“裸 Codex 对话”与“Better Codex 看板”在任务遗漏、恢复、返工和 Session 数上的差异；不先迁移重要项目。
- 收藏库联动：**已收藏 / 值得跟进**

### 2. tmchao7/local-vision-mcp

- GitHub: https://github.com/tmchao7/local-vision-mcp
- 一句话用途：让 Codex 等文本 Agent 通过本地 Ollama 视觉模型分析截图和图片，只把结构化文字结果返回给 Agent。
- 为什么值得看：图片字节不离开本机；单一 `vision_analyze` 工具支持 UI、OCR、general 以及 before/after 对比，并有路径 allowlist、symlink escape 防护和 JSON Schema 约束。它可以成为 Chrome DevTools MCP 的视觉补充层，而不是另一个完整多模态 Agent。
- 适合怎么用：Codex 修改 UI → 截图 → 本地视觉模型检查布局/错误 → 返回结构化报告 → Codex 再修复；也适合分析本地软件报错截图。
- 本地部署/测试成本：**中**。需要 Node.js 20+、Ollama 和 qwen3-vl/gemma3 等视觉模型；README 当前主要标注 macOS/Linux，Windows 原生支持未被列为验证目标。
- 当前状态：**REVIEW**
- 下一步建议：优先在 WSL2/兼容环境做 10 张 UI 截图测试，记录准确率、单图耗时、显存占用和误报；Windows 原生链路明确前不进入主工作流。
- 收藏库联动：**已收藏 / 值得跟进**

### 4. kytianhong/codex3d

- GitHub: https://github.com/kytianhong/codex3d
- 一句话用途：用结构化 MCP 工具让 Codex 控制 Blender，并用渲染证据验证 3D 结果。
- 为什么值得看：它刻意不暴露任意 Python/eval/exec/shell，而采用 allowlist Action、localhost bridge、稳定对象 UUID、快照恢复和视觉交付 gate；这个“生成→检查→证据→恢复”的设计比单纯让 Agent 写 Blender Python 更适合长期自动化。
- 适合怎么用：研究 Codex 驱动 3D 产品示意、简单动画、视频资产生成；更重要的是抽取其安全执行与视觉验收模式，迁移到其他创作工具。
- 本地部署/测试成本：**中～高**。需要 Blender、Python、Codex/MCP；当前参考验证环境偏 macOS，因此暂不建议在 Windows 主环境直接投入。
- 当前状态：**REVIEW**
- 下一步建议：先只研究其 allowlist、snapshot、render validation 三层设计；后续确有 3D 项目需求时，再在独立 Blender 环境跑最小场景闭环。
- 收藏库联动：**已收藏 / 值得跟进**

## 今日 Idea

### P0 — Codex Task Operating Layer

**来源：** better-codex + AgentsView + Codex Harness Bake-off

把“Agent 能不能完成任务”进一步升级为“复杂项目能不能被持续管理”：Better Codex 管任务拆解、分派和状态，AgentsView 管 Session/Token/耗时，Harness Bake-off 管执行方式。用统一项目比较任务遗漏率、返工、恢复成本和单位有效成果 Token，最后决定是否需要长期任务控制层。

### P1 — Local Visual QA Sidecar

**来源：** local-vision-mcp + Chrome DevTools MCP + Codex

建立两级 UI 验收：Chrome DevTools MCP 负责 DOM/Console/Network/Performance 的确定性证据，本地视觉模型负责布局、截断、视觉异常和 before/after；只有两层都通过才交付 Web/UI 任务。

## 今日投入顺序
