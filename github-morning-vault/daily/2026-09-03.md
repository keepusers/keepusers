### 1. github/github-mcp-server — TRY
- 链接：https://github.com/github/github-mcp-server
- 一句话用途：GitHub 官方 MCP Server，让 Codex/Agent 直接读取仓库、代码、Issue、PR 并执行 GitHub 工作流。
- 为什么值得看：官方维护，属于 Codex 与 GitHub 自动化之间最基础、最通用的连接层；比继续堆第三方 GitHub wrapper 更值得优先验证。
- 适合怎么用：让 Codex 查询仓库、分析代码、管理 Issue/PR，并作为 Morning Vault 自动化的标准 GitHub 接口。
- 本地部署/测试成本：低～中；先以最小权限配置测试，不建议一开始开放全部写权限。
- 当前状态：TRY
- 下一步建议：建立测试仓库，验证读取文件→创建 Issue→分析 PR 三条链路和权限边界。
- 收藏库联动：已收藏

### 4. farion1231/cc-switch — REVIEW
- 链接：https://github.com/farion1231/cc-switch
- 一句话用途：跨平台桌面管理 Claude Code、Codex、OpenCode 等 Agent 的配置、Provider、MCP 和 Skills。
- 为什么值得看：随着 Codex/MCP/Skills 数量增加，配置管理本身会成为维护成本；该项目把多 Agent 配置集中到桌面层。
- 适合怎么用：Windows 上统一管理多个 coding agent 的 MCP、Skills 和 Provider 配置，减少手改配置文件。
- 本地部署/测试成本：低～中；桌面应用，但涉及凭据和配置写入，必须先做备份和权限检查。
- 当前状态：REVIEW
- 下一步建议：只导入一个测试 Agent 配置，确认备份、回滚和敏感凭据存储方式后再考虑接管主环境。
- 收藏库联动：已收藏
