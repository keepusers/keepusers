## 今日精选

### shshalom/voicesmith-mcp — TRY
- 链接：https://github.com/shshalom/voicesmith-mcp
- 用途：通过 MCP 给 Codex/Cursor/Claude Code 增加完全本地的 TTS + STT。
- 为什么值得看：明确支持 Codex；Kokoro ONNX + faster-whisper，本地离线；安装器可自动配置 MCP。
- 适合怎么用：作为 Codex 语音输入/输出层，先验证“说话下指令 + Codex 语音反馈”。
- 部署/测试成本：中；Python 3.11+、espeak-ng、mpv，模型约数百 MB。
- 下一步建议：在独立测试目录部署，验证 Windows 音频依赖和 Codex MCP 单 Session 体验。
- 收藏库联动：已收藏

### Leo0186/openchatcut — TRY
- 链接：https://github.com/Leo0186/openchatcut
- 用途：local-first、Agent-native 的多轨 AI 视频编辑器，支持 Codex/Claude Code、Agent Skills、MCP 与 Remotion 渲染。
- 为什么值得看：不是单纯“生成视频”，而是让 Agent 直接读写可继续人工编辑的真实时间线工程，和 Codex 自动化结合价值高。
- 适合怎么用：作为 AI Video Factory 的后期编辑/装配层，让 Codex 根据脚本自动创建和修改时间线。
- 部署/测试成本：中高；需要 Node/桌面开发与视频渲染环境，仓库体量较大。
- 下一步建议：先跑官方示例工程，测试 Codex 是否能稳定完成“导入素材→剪辑→字幕→导出”。
- 收藏库联动：已收藏

### h1papc11/voice-mcp-agent — REVIEW
- 链接：https://github.com/h1papc11/voice-mcp-agent
- 用途：本地语音工作台，整合 Whisper STT、多 TTS 引擎、声音克隆、桌面听写和 MCP Agent 自定义声音。
- 为什么值得看：比单一 TTS MCP 更接近完整“声音生产工作台”，适合后续歌曲/配音/Agent Voice 工作流研究。
- 适合怎么用：与现有 LocalAI/LA-Studio 候选横向比较，重点看声音克隆质量、Windows 体验与 MCP 接入。
- 部署/测试成本：高；Tauri/Rust/Bun/多语音引擎，仓库和依赖较重。
- 下一步建议：暂不直接装，先检查 Windows 安装链、支持的 TTS 引擎与显存需求，再决定是否升级 TRY。
- 收藏库联动：已收藏

### linjuhon/video20-ai-workbench — REVIEW
- 链接：https://github.com/linjuhon/video20-ai-workbench
- 用途：把长视频拆成 20 段故事板、关键帧、分段视频，再通过 ComfyUI 路由和 FFmpeg 组装。
- 为什么值得看：它展示了比“单 Prompt 生成视频”更可控的分镜生产架构，可直接为现有 AI Video Factory Idea 提供工程参考。
- 适合怎么用：不一定完整部署，可重点拆解 storyboard state、关键帧持久化、ComfyUI workflow routing 和最终装配方式。
- 部署/测试成本：高；依赖 ComfyUI、视频模型、FFmpeg 和较大 GPU 资源。
- 下一步建议：先阅读架构与 workflow 模板，不急于下载模型；提取可复用设计后再决定 TRY。
