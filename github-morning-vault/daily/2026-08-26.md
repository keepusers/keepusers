### 1. akitaonrails/ai-memory
- 链接：https://github.com/akitaonrails/ai-memory
- 一句话用途：给 Codex、Claude Code、Cursor 等编码代理提供跨会话、跨代理的长期记忆与任务交接。
- 为什么值得看：直接解决“换 Session / 换 Agent 后上下文丢失”的问题，官方 README 明确支持 Codex、Claude Code、Cursor、Gemini CLI 等，并能在同一项目目录继续未完成任务。
- 适合怎么用：作为 Codex 项目的长期记忆层，保存架构、失败方案、决策、TODO 和跨 Session handoff。
- 本地部署/测试成本：中；Linux/macOS 支持成熟，Windows 原生仍为 Experimental，WSL2 是更稳妥方案；涉及 Rust/MCP/hooks 配置。
- 当前状态：`TRY`
- 下一步建议：优先在一个小型 Codex 测试项目中验证跨 Session 记忆，再决定是否全局接入。
- 收藏库联动：**已收藏**

### 2. mudler/LocalAI
- 链接：https://github.com/mudler/LocalAI
- 一句话用途：本地运行 LLM、视觉、语音、图像和视频，并提供 OpenAI/Anthropic/ElevenLabs 兼容 API。
- 为什么值得看：一个后端统一多模态，本地优先；近期版本强化了声音克隆、本地视频/Avatar、TTS 与 Agent/MCP 能力，与你的声音合成和 AI 视频方向高度相关。
- 适合怎么用：给 Codex/本地工具提供统一的本地模型 API，也可作为语音克隆和视频生成工作台的基础层。
- 本地部署/测试成本：中高；Docker 最方便，CPU 可运行，但视频/语音等实际体验更依赖 GPU 与模型体积。
- 当前状态：`TRY`
- 下一步建议：先用 Docker 只启动一个轻量 LLM/TTS 后端，验证 API，再扩展语音和视频能力。
- 收藏库联动：**已收藏**

### 3. microsoft/markitdown
- 链接：https://github.com/microsoft/markitdown
- 一句话用途：把 PDF、Office 等文档转换成适合 LLM/Codex 读取的 Markdown。
- 为什么值得看：与你之前“降低 PDF/PPT 给 Codex 阅读时的 Token 消耗”需求高度吻合，体积和复杂度都远低于大型 RAG 系统。
- 适合怎么用：作为 `文档 → Markdown → Codex` 的预处理层，后续可加入批处理、目录索引和摘要。
- 本地部署/测试成本：低；Python 工具链，适合快速验证。
- 当前状态：`TRY`
- 下一步建议：拿一份常用 PDF/PPT 做转换，对比原文件与 Markdown 的可读性和 Token 成本。
- 收藏库联动：**已收藏**

### 4. apache/maka
- 链接：https://github.com/apache/maka
- 一句话用途：Apache 孵化中的 local-first AI Agent 工作区，记录模型消息、工具调用、权限决策和运行结果。
- 为什么值得看：核心理念与 Codex 项目管理非常接近，强调本地数据、可恢复执行记录、CLI/Desktop/Eval 共用运行时，并支持 Read/Write/Edit/Bash 等工具。
- 适合怎么用：研究“本地 Agent 工作区 + 可恢复执行日志 + 多模型”的架构，未来可能替代或补充现有 Agent 工作台。
- 本地部署/测试成本：中高；当前 Windows 仅 unsigned preview，README 要求 Node.js 22.19+、npm、Git、ripgrep，并建议从源码运行。
- 当前状态：`REVIEW`
- 下一步建议：暂不作为主力安装，持续关注 Windows 支持和正式 Release；先读架构文档。
- 收藏库联动：**已收藏**

### 5. harry0703/MoneyPrinterTurbo
- 链接：https://github.com/harry0703/MoneyPrinterTurbo
- 一句话用途：根据主题/关键词自动生成脚本、素材、配音、字幕并合成短视频。
- 为什么值得看：是成熟的 AI 短视频自动化工作流，可直接参考其“LLM → 素材 → TTS → 字幕 → FFmpeg”流水线，而不一定整套照搬。
- 适合怎么用：拆解其中的自动视频流水线，结合你自己的声音克隆模型和本地生成工具。
- 本地部署/测试成本：中；Python、多媒体依赖与素材/模型/API 配置较多。
- 当前状态：`REVIEW`
- 下一步建议：先研究流水线和模块边界，优先复用其 FFmpeg、字幕和任务编排思路。
- 收藏库联动：**已收藏**

### 6. Comfy-Org/ComfyUI
- 链接：https://github.com/Comfy-Org/ComfyUI
- 一句话用途：节点式本地图像/视频生成与 AI 工作流编排平台。
- 为什么值得看：生态成熟、可视化节点工作流适合把模型推理流程固定下来，也很适合作为 Codex 自动生成/修改 workflow 的目标平台。
- 适合怎么用：本地图像/视频生成；未来可让 Codex 帮你维护 workflow JSON、模型目录和批处理任务。
- 本地部署/测试成本：中高；基础框架不难，但模型占用显存和磁盘较大，视频模型成本更高。
- 当前状态：`REVIEW`
- 下一步建议：如果进入 AI 视频实操阶段，再设为 TRY；当前先保留为核心候选工作台。
- 收藏库联动：**已收藏**

## 今日 Idea
1. **Codex Persistent Workspace**：Codex + ai-memory + GitHub 项目目录，形成跨 Session 自动记忆、决策记录和任务恢复系统。
2. **Local Multimodal Hub**：LocalAI 作为统一 API 层，把本地 LLM、TTS、声音克隆、图像和视频接给 Codex。
3. **Document-to-Codex Pipeline**：MarkItDown 批量把 PDF/PPT/Word 转 Markdown，自动生成目录、摘要与 Codex 输入包，降低 Token 消耗。
4. **AI Video Factory**：借鉴 MoneyPrinterTurbo 的流水线，用 ComfyUI/LocalAI + 自有声音模型 + FFmpeg 构建本地短视频自动生产线。

## 今日结论
优先实际测试：`ai-memory`、`LocalAI`、`markitdown`。`Maka`、`MoneyPrinterTurbo`、`ComfyUI` 先进入 REVIEW，避免同时铺太多环境。
