## 1. code-yeongyu/lazycodex
- GitHub: https://github.com/code-yeongyu/lazycodex
- 一句话用途：给 Codex 增加项目记忆、规划、持续执行、验证闭环、Skills/Hooks 与多 Agent 编排的 Agent Harness。
- 为什么值得看：不是单一 MCP，而是直接改造 Codex 的工作方式；提供 init-deep、ulw-plan、start-work、ulw-loop 等流程，把“写完即完成”改成“证据验证后完成”。近期仍在持续演进，并明确支持 Codex App/CLI 与 Windows。
- 适合怎么用：先在独立测试仓库跑复杂开发任务，对比裸 Codex 与 LazyCodex 在计划质量、跨轮次连续性、测试验证和 Token/额度消耗上的差异。
- 本地部署/测试成本：中。需要 Codex + Node/npm/npx；不建议直接覆盖主工作环境，先独立仓库验证 Hooks 和配置改动。
- 当前状态：`TRY`
- 下一步建议：选一个真实但可回滚的代码项目，分别用裸 Codex 与 LazyCodex 完成同一任务，记录耗时、调用次数、失败返工、验证完整度。
- 收藏库联动：**已收藏 / 值得跟进**

## 2. Team-Volt/agent-lcm
- GitHub: https://github.com/Team-Volt/agent-lcm
- 一句话用途：给 Codex、Cursor、VS Code、Copilot、Claude Code、OpenCode 等 Agent 建立共享的 local-first 长期会话记忆。
- 为什么值得看：它把经过清理的事件归档作为 source of truth，索引、摘要和图谱都可以重建；重点不是“再做一个 RAG”，而是保存不同 Agent 的真实历史并允许跨 Harness 检索。
- 适合怎么用：作为 Codex Persistent Workspace 的候选底座，让旧 Codex Session、其他 coding agent 的决策和执行历史可以被新会话按证据检索。
- 本地部署/测试成本：中。需要接入不同 Agent 的 importer/MCP；项目较新，应先验证 Windows、隐私清理、索引稳定性和历史导入质量。
- 当前状态：`TRY`
- 下一步建议：只导入一个非敏感 Codex 测试项目的 5–10 个 Session，测试跨 Session 找回“为什么这样改”“失败方案是什么”“上次做到哪里”。
- 收藏库联动：**已收藏 / 值得跟进**

## 3. paperclipai/paperclip
- GitHub: https://github.com/paperclipai/paperclip
- 一句话用途：用一个本地可控的管理面板组织多个 AI Agent 的目标、任务、预算、治理和工作进度。
- 为什么值得看：它把多 Agent 从“几个子 Agent 并行跑”提升到更长期的组织管理层：目标、组织结构、成本、治理、协调都进入统一控制面，适合研究长期自治项目如何管理。
- 适合怎么用：不建议立刻接管现有 Codex；更适合作为未来“AI 项目团队控制台”的架构参考，观察它如何管理 Agent 生命周期、预算和目标对齐。
- 本地部署/测试成本：中高。Node.js Server + React UI；真正成本在于接入多个 Agent 后的权限、预算与任务治理，而非单纯安装。
- 当前状态：`REVIEW`
- 下一步建议：先阅读任务/预算/Agent adapter 数据模型，再决定是否用一个低风险自动化项目做 2–3 Agent PoC。
- 收藏库联动：**已收藏 / 值得跟进**

## 4. noobnooc/agent
- GitHub: https://github.com/noobnooc/agent
- 一句话用途：一组面向 Codex 的小型工程纪律 Skills，重点提升 Debug、范围控制、依赖判断、测试与提交前审计可靠性。
- 为什么值得看：项目很小，但 better-codex 与 wtf 两类 Skill 直接针对 AI 编码常见问题：症状式修补、范围失控、过期编辑、遗漏 secrets/env/database/deployment 风险。相比再装大型 Harness，适合拆解成自己的私有 Skill。
- 适合怎么用：不要整套照搬；提取其中可靠性检查框架，与现有 local-skills-mcp/Skill Governance 体系结合，形成自己的 Codex Quality Gate。
- 本地部署/测试成本：低。核心是 SKILL.md，主要成本是审阅规则并按自己的项目习惯改写。
- 当前状态：`REVIEW`
- 下一步建议：先只评估 better-codex 和 wtf，挑 5–10 条真正有效的规则做私有 quality-gate Skill，在测试仓库比较修改前后的返工率。
- 收藏库联动：**已收藏 / 值得跟进**

## 今日 Idea

### P0 — Codex Harness Bake-off
来源：LazyCodex + 现有 agent-rack / codex-control-plane-mcp / Skills

建立固定基准任务，对“裸 Codex / LazyCodex / 现有模块化组合”比较：计划质量、完成率、返工次数、验证证据、Token/额度消耗。最终只保留真正提升结果的 Harness，避免工具层无限叠加。

### P0 — Cross-Agent Session Memory
来源：agent-lcm + ai-memory + gno

把“项目资料知识库”和“Agent 历史记忆”分层：gno 管文档/代码事实，agent-lcm 管真实 Session/决策/执行历史，再由 Codex 按需检索，避免把所有东西混成一个 RAG。

### P1 — Codex Quality Gate Skill
来源：noobnooc/agent + local-skills-mcp

建立自己的提交前/任务完成前 Skill：检查根因是否解决、是否引入重复真相、测试是否覆盖、是否存在 secrets/env/deployment 风险，并要求输出验证证据。
