## 1. Yeachan-Heo/oh-my-codex

- GitHub: https://github.com/Yeachan-Heo/oh-my-codex
- 一句话用途：在原生 Codex CLI 外增加规划、Skills、Hooks、持久目标、团队协作与运行状态层。
- 为什么值得看：它不替换 Codex，而是把 Codex 作为执行引擎；仓库已形成较完整的 workflow、skills、hooks、`.omx/` 状态与 doctor/exec 验证体系。与昨天的 LazyCodex 属于直接竞品，正适合纳入 Harness Bake-off，而不是盲目叠加。
- 适合怎么用：固定一个真实开发任务，对比裸 Codex、LazyCodex、oh-my-codex 的计划质量、返工、验证证据、并行能力和额度消耗。
- 本地部署/测试成本：中。需要已有 Codex CLI 与 Node/npm；macOS/Linux 是主路径，Windows 原生支持较弱，Windows 用户更适合 WSL2/psmux 路线。
- 当前状态：`TRY`
- 下一步建议：只在独立测试仓库/WSL2 安装，加入现有 Codex Harness Bake-off；不要直接覆盖主 Codex 配置。
- 收藏库联动：**已收藏 / 值得跟进**

## 2. mudler/LocalAGI

- GitHub: https://github.com/mudler/LocalAGI
- 一句话用途：自托管 Agent 平台，可作为 OpenAI Responses API 风格的本地 Agent 后端，并双向接入 MCP。
- 为什么值得看：收藏库已有同作者 LocalAI 作为本地模型/多模态底座；LocalAGI 正好补“Agent Runtime”层。它既能消费 MCP，也能把 Agent 管理能力作为 MCP 暴露出来，适合把本地模型从“API 服务”升级成可暂停、启动、配置和编排的 Agent 服务。
- 适合怎么用：LocalAI 承担模型推理，LocalAGI 承担 Agent 生命周期与工具编排，Codex/其他 MCP Client 负责上层任务。
- 本地部署/测试成本：中。自托管，需要配置模型后端和 Agent；可先用现有 LocalAI/Ollama 类后端做最小验证。
- 当前状态：`TRY`
- 下一步建议：建立一个只含 1 个 Agent + 1 个 MCP 工具的最小实例，验证创建/暂停/恢复/调用链，再决定是否进入长期本地 AI 基础设施。
- 收藏库联动：**已收藏 / 值得跟进**

## 3. joaquingit1/loqui

- GitHub: https://github.com/joaquingit1/loqui
- 一句话用途：本地会议转录、说话人区分、摘要与可被 Agent 查询的会议记忆库。
- 为什么值得看：它把“录音转文字”进一步变成结构化、可长期检索的会议知识层；MCP 对会议库采用只读设计，Agent 能搜索会议、转录和摘要但不能修改原始记录，边界清晰。支持 Windows/macOS，和已有 hearsay/video-context-mcp 的定位不同：Loqui 更适合长期会议资产。
- 适合怎么用：工作会议/培训录音 → 本地转录与摘要 → MCP → Codex 查询“上次会议决定了什么/谁负责什么”。
- 本地部署/测试成本：中。桌面端 + 本地转录/AI Provider 配置；实际成本主要取决于转录模型和是否使用本地摘要模型。
- 当前状态：`REVIEW`
- 下一步建议：先用一段非敏感的 10–20 分钟中文会议录音验证中文识别、说话人区分和 MCP 检索，再决定是否升 `TRY`。
- 收藏库联动：**已收藏 / 值得跟进**

## 4. JuliusBrussee/caveman

- GitHub: https://github.com/JuliusBrussee/caveman
- 一句话用途：压缩 AI coding agent 的冗长输出，目标是在保留推理/执行能力的同时降低输出 Token 与账单。
- 为什么值得看：现有收藏大量关注“给 Codex 增加更多能力”，但能力层越厚越容易增加上下文和输出成本。Caveman 反向关注输出压缩，和 Ratel Local 的 MCP 上下文治理形成互补：一个减少工具上下文，一个减少 Agent 输出冗余。
- 适合怎么用：在固定 Codex 任务上比较原始输出与压缩输出的 token、可读性、错误率、返工次数，判断节省是否真实而非单纯变短。
- 本地部署/测试成本：低～中。适合作为 Skill/proxy/wrapper 做隔离 A/B，不需要引入大型模型基础设施。
- 当前状态：`REVIEW`
- 下一步建议：不要直接全局启用；选 3 类任务（代码修改、Debug、研究总结）记录 Token 与完成质量，只有“成本下降且返工不增加”才升 `TRY`。
- 收藏库联动：**已收藏 / 值得跟进**

## 今日新增 Idea

### P0 — Local Agent Runtime Stack

`LocalAI + LocalAGI + MCP + Codex`

把现有 LocalAI 从单纯模型 API 层扩展为完整本地 Agent Runtime：LocalAI 负责模型/多模态推理，LocalAGI 负责 Agent 生命周期和 MCP 编排，Codex 负责高层开发与操作任务。先用单 Agent 最小实例验证，不先搭复杂多 Agent 网络。

### P1 — Meeting-to-Project Memory

`Loqui + gno/本地知识库 + Codex`

会议结束后保留原始转录和摘要，Codex 通过只读 MCP 查询会议决定，再把确认后的 action item/技术决策沉淀到项目知识库。会议历史和项目事实分层，避免把未经确认的口语内容直接写成项目事实。

### P1 — Agent Efficiency Benchmark

`Caveman + Ratel Local + Codex Harness Bake-off`

在现有 Harness Bake-off 中增加“效率”指标：输入上下文 Token、输出 Token、完成时间、返工次数和最终任务通过率。目标不是追求最短回答，而是找到单位有效任务成果的最低 Token 成本。
