## 1. lhxll07/Lociant
- GitHub: https://github.com/lhxll07/Lociant
- 一句话用途：把 Android 手机、Linux 主机或 RK 板变成本地 AI 设备节点，并通过 MCP 把屏幕、点击、传感器、摄像头和本地模型能力交给 Codex 等 Agent。
- 为什么值得看：它把“本地 AI”从电脑软件扩展到了真实设备执行层；Android 可做屏幕读取/点击/表单操作，设备之间还能在局域网发现并共享模型与工具。项目 2026-05-17 创建，仓库元数据显示 2026-08-20 仍有 push，MIT License。
- 适合怎么用：先拿闲置 Android 手机做 Agent Device Node，让 Codex 经 MCP 调用手机能力；长期可研究“电脑 Codex 规划 + 手机执行/感知”的跨设备自动化。
- 本地部署/测试成本：中～高。Android 侧需要构建/安装并授权设备能力；若只测 Linux runtime 成本更低。涉及真实设备操作，必须先限制权限和测试账号。
- 当前状态：`TRY`
- 下一步建议：用一台非主力 Android 手机，只开放 1～2 个低风险能力，验证 `Codex → MCP → 手机读取/点击 → 返回证据` 最小闭环，不先接消息、支付等敏感应用。
- 收藏库联动：**已收藏 / 值得跟进**

## 2. ivanopcode/cocoaskills
- GitHub: https://github.com/ivanopcode/cocoaskills
- 一句话用途：本地 Agent Skill 包管理器，为 Codex/Claude/Cursor/Gemini 等提供可复现、带依赖和安全审计的项目级 Skill 安装。
- 为什么值得看：Morning Vault 已经有 Skill 发现、加载和生命周期工具，但 CocoaSkills 更强调 content-hash 锁定、依赖关系、项目级可复现安装和 security audit，适合解决“不同电脑/项目 Skill 漂移”。仓库 2026-05-07 创建，2026-08-27 有 push，Apache-2.0。
- 适合怎么用：作为现有 `Skill Package Lifecycle` 的候选实现，与 `vercel-labs/skills` 做 A/B，不应两套长期并存。
- 本地部署/测试成本：低。Python CLI 为主；测试应放在独立仓库，避免污染现有 Codex Skill 目录。
- 当前状态：`REVIEW`
- 下一步建议：固定 3 个自建 Skill，比较 CocoaSkills 与现有方案在锁版本、跨机复现、卸载清理、安全检查上的差异，只保留一个包管理底座。
- 收藏库联动：**已收藏 / 值得跟进**

## 3. maxbaluev/accreted-intelligence
- GitHub: https://github.com/maxbaluev/accreted-intelligence
- 一句话用途：给 Codex/Claude/OpenCode 等建立 local-first “Work Model”，从真实任务结果中积累可复用工作经验。
- 为什么值得看：它关注的不是普通聊天记忆，而是把 Agent 的工作生命周期、结果与经验沉淀成跨 host 的本地底座；Codex CLI 可通过 MCP + notify hook 接入。这个方向与现有 Agent LCM/ai-memory 有重叠，但“从真实 outcome 学工作模式”的思路值得单独验证。
- 适合怎么用：放进现有 Cross-Agent Session Memory/Observability Bench，研究“项目事实”“会话历史”“可复用工作经验”是否应该三层分离。
- 本地部署/测试成本：中。需要接入 MCP/host hooks；仓库规模和社区采用仍小，且元数据显示最近 push 为 2026-07-05，维护活跃度需要继续观察。
- 当前状态：`REVIEW`
- 下一步建议：先只读架构与数据模型，不进入主环境；若数据层能明确区别于 Agent LCM，再用 5～10 个真实 Codex Session 做 outcome-learning A/B。
- 收藏库联动：**已收藏 / 值得跟进**

## 4. Ya-KARAS/AgentControlPlane
- GitHub: https://github.com/Ya-KARAS/AgentControlPlane
- 一句话用途：把 Web AI 对话派发给本地 Codex/OpenCode/Claude Code 等执行器，并返回改动文件、测试证据、usage 与可继续执行状态。
- 为什么值得看：重点不是再做一个 coding agent，而是把“远端/网页规划”和“本机编码执行”拆开，并要求本地执行器返回持久化证据；同时覆盖 Codex 和 Windows。仓库 2026-08-13 创建、2026-08-27 有 push，仍属早期 preview。
- 适合怎么用：作为现有 `codex-control-plane-mcp` / agent-rack 的对照组，重点研究跨设备派发、executor routing、evidence contract 和 continuation state，而不是立即替换现有控制平面。
- 本地部署/测试成本：中。需要本地执行器与 relay/control plane 配置；项目仅少量社区采用，AGPL-3.0，适合沙箱研究。
- 当前状态：`NEW`
- 下一步建议：只拆解它的“任务 brief → executor → changed files/tests/usage → continuation”证据协议；若协议设计明显优于现有方案，再做本地测试。
- 收藏库联动：**已收藏 / 值得跟进**

## 今日可执行 Idea

### P0 — Cross-Device Codex Node
`Codex + Lociant + MCP + 闲置 Android`

把闲置 Android 变成低权限执行/感知节点：Codex 在电脑上负责计划，手机只承担明确授权的屏幕读取、点击、摄像头/传感器任务，并把执行证据返回电脑。第一阶段只做测试 App 或浏览器页面，建立 allowlist 和人工确认点。

### P1 — Skill Reproducibility Bake-off
`CocoaSkills + vercel-labs/skills + private SKILL.md`

固定 3 个私有 Skill，在两个测试项目中比较安装锁定、依赖、安全审计、更新、回滚和卸载残留。目标不是再增加一个 Skill 工具，而是选出唯一长期包管理底座。

### P1 — Agent Experience Layer
`accreted-intelligence + Agent LCM + gno`

尝试把长期上下文拆成三层：`gno = 项目事实`、`Agent LCM = 会话/决策历史`、`AccInt = 从任务 outcome 提炼的工作经验`。只有第三层能产生可量化的返工下降，才值得保留。

## 今日结论
今天没有继续堆同质 RAG/多 Agent 框架。最值得实际测试的是 **Lociant**：它把 Codex 的工具边界从 PC 扩展到手机/边缘设备。其余三个项目更适合进入现有 Bake-off/治理体系，通过对照测试决定是否保留。
