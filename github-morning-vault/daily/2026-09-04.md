## 今日新增

### 1. lakpriya1s/agent-rack — TRY
- GitHub: https://github.com/lakpriya1s/agent-rack
- 一句话用途：把 Codex、Claude Code、OpenCode 等 CLI 编码 Agent 统一包装成 MCP 子 Agent。
- 为什么值得看：支持同步任务、后台 Session、日志流、继续输入、取消任务，并提供结构化代码审查；适合把 Codex 从单 Agent 使用升级到可委派的 Agent Rack。
- 适合怎么用：让主 Codex 负责规划，再把实现、审查、测试分派给隔离的 CLI Agent。
- 本地部署/测试成本：中；需要 Node/MCP 环境以及本机已有对应 CLI Agent。
- 当前状态：TRY
- 下一步建议：建立独立测试仓库，只接 Codex + 一个第二 Agent，验证后台任务、代码审查和任务取消，不直接接生产项目。
- 收藏库联动：已收藏 / 值得跟进

### 2. tsarihan/model-council-mcp-codex — TRY
- GitHub: https://github.com/tsarihan/model-council-mcp-codex
- 一句话用途：让 Codex 把同一个问题交给本地与云端多个模型组成“模型委员会”交叉评审。
- 为什么值得看：支持 individual、categorized、deconflicted、pooled、dialectic 等多种综合模式，可把单模型判断升级为多模型分歧分析，尤其适合技术方案、研究结论和高成本决策。
- 适合怎么用：重要架构选择、论文结论核验、复杂 Debug 方案先由多个模型独立判断，再让 Judge 汇总冲突。
- 本地部署/测试成本：中；可接 Ollama/vLLM 等本地模型，也可混合云模型，成本取决于委员会规模。
- 当前状态：TRY
- 下一步建议：先使用 2 个本地模型 + Codex 做一次真实技术决策 A/B，比较质量提升与 Token/时间成本。
- 收藏库联动：已收藏 / 值得跟进

### 3. Kirachon/context-engine — REVIEW
- GitHub: https://github.com/Kirachon/context-engine
- 一句话用途：给 Codex 提供本地 workspace 索引、语义检索、规划和 Review 的统一 Context Engine MCP。
- 为什么值得看：不仅做代码检索，还把 retrieval、planning、review 放在同一个本地 MCP 中，并提供 Windows/Codex 部署说明。
- 适合怎么用：作为大型 Codex 项目的上下文侧车，让 Agent 先检索和规划，再读取少量真正相关文件。
- 本地部署/测试成本：中。
- 当前状态：REVIEW
- 下一步建议：暂不安装；先与 gno、codegraph、Graphify 的职责做矩阵比较，确认它是否能减少现有工具重叠。
- 收藏库联动：已收藏 / 值得跟进

### 4. CoreEpoch/mcp-soundfx — REVIEW
- GitHub: https://github.com/CoreEpoch/mcp-soundfx
- 一句话用途：让 MCP Agent 在本机 NVIDIA GPU 上用 Stable Audio Open 生成音效 WAV。
- 为什么值得看：补齐现有 RVC/TTS/REAPER 工作流中的“音效生成”环节；模型首次下载后可离线生成，支持时长、负面提示词和质量步数控制。
- 适合怎么用：给 AI 视频、短片、游戏 Demo 自动生成 UI、环境、撞击、转场等 SFX，再交给 REAPER 或视频流水线混音。
- 本地部署/测试成本：中高；需要 NVIDIA GPU 和 Stable Audio Open 模型。
- 当前状态：REVIEW
- 下一步建议：先确认 RTX 5060 Ti 16GB 上的显存占用和生成速度，再决定是否进入 TRY。
- 收藏库联动：已收藏 / 值得跟进
