## 1. block/berd

- GitHub：https://github.com/block/berd
- 一句话用途：Block 开源的桌面级 AI Agent 工作区，统一承载本地项目、模型、Provider、Skills、Extensions、Automation 和 Session。
- 为什么值得看：它不是又一个聊天壳，而是把 Agent 的项目、上下文、配置和历史集中到一个本地桌面工作面；底层通过 Goose/ACP 连接 Agent，适合研究“多 Agent 多模型统一工作台”的实际形态。Apache-2.0，支持 Windows/macOS/Linux。
- 适合怎么用：作为 Codex、Goose、Claude Code 等工具的对照工作区，观察任务组织、Session 连续性、Provider/Skill 管理和本地文件上下文如何统一；不建议立刻替换现有 Codex 主流程。
- 本地部署/测试成本：中。需要 `just setup`、pnpm、Rust/Tauri 以及 Goose sidecar，首次构建成本明显高于普通 MCP；如果只使用发布包，成本较低。
- 当前状态：REVIEW
- 下一步建议：先用发布版或独立分支测试 Windows 启动、Codex/Goose 接入、项目/Session 持久化和 Skill/Automation 管理；重点记录它与 better-codex、AgentsView 的职责边界。
- 收藏库联动：已收藏 / 值得跟进

## 2. dovvnloading/Graphlink

- GitHub：https://github.com/dovvnloading/Graphlink
- 一句话用途：本地优先的图形化 AI 工作区，把对话、研究、Python 运行、图表和预算可控 Agent 放进可分支的视觉画布。
- 为什么值得看：它与已有 codegraph/Graphify 的区别在于“工作过程图”而不是“代码知识图谱”；支持 Ollama、llama.cpp 和云端模型，可撤销的多步骤 Agent 也更接近可审计实验台。2026-09-05 仍有 push，MIT License。
- 适合怎么用：把论文调研、实验数据分析、AI 视频方案拆成节点：问题→检索→脚本/Python→图表→结论，再把确认后的结论写入 gno 或项目 Markdown 知识库。
- 本地部署/测试成本：中。需要 Python 环境和本地模型/云模型配置；图形工作区本身不重，但长期价值取决于节点执行稳定性和导出能力。
- 当前状态：TRY
- 下一步建议：用一个真实的小型研究任务测试“分支对话→Python→图表→预算控制→结果导出”闭环，并比较它与 Codex Research Workbench 的重复度。
- 收藏库联动：已收藏 / 值得跟进

## 3. KrishBhimani/argus-code

- GitHub：https://github.com/KrishBhimani/argus-code
- 一句话用途：local-first 的 Agent 可观测性工具，记录每个 Session 的工具调用、子 Agent 提示、预算超支、错误、Token 和成本。
- 为什么值得看：Morning Vault 已有 AgentsView，但 Argus 的定位更偏“调试 Agent 到底做了什么”，包括哪一轮超预算、哪些工具执行过、哪个子 Agent 被传入了什么；SQLite 本地存储，数据不离机。仓库 2026-09-02 仍有 push，MIT License。
- 适合怎么用：作为 Codex Harness Bake-off 的第二个观测样本，专门记录失败任务、工具链路、异常和预算拐点；不与 AgentsView 并行长期部署，先做固定任务集比较。
- 本地部署/测试成本：低～中。Python/FastAPI/React/SQLite，GPU 非必需；主要成本在于接入数据格式和清洗不同 Agent Session。
- 当前状态：REVIEW
- 下一步建议：选 5 个固定 Codex 任务，比较 Argus 与 AgentsView 在 Session 完整性、Token/成本统计、失败定位和跨 Agent 兼容性上的差异；若 Argus 能提供更细的工具级证据，再考虑保留。
- 收藏库联动：已收藏 / 值得跟进

## 今日 Idea

`Berd + Codex/Goose + better-codex + AgentsView`

目标：不追求再造一个 Agent，而是比较统一桌面工作区在项目管理、Session 连续性、Skill/Provider 管理和真实任务完成率上的增益。

`Graphlink + Codex Research Workbench + gno`

目标：把研究任务拆成可分支、可回滚、可复用的“问题—证据—计算—图表—结论”节点图，确认后的结论再进入长期知识库。

`argus-code + AgentsView + Codex Harness Bake-off`

目标：将 Session 级指标与工具级执行证据合并，区分“Token 变少”与“真正减少返工/错误”的差异。
