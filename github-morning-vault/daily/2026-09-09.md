## 1. kajisho5/ffmpeg-skill

GitHub: https://github.com/kajisho5/ffmpeg-skill

- **一句话用途**：把 FFmpeg/FFprobe 封装成 Codex 可直接调用的本地视频编辑 Skill + MCP 工具集。
- **为什么值得看**：2026-09-03 创建后快速获得数百 Star，且 2026-09-08 仍有提交；不是单纯 FFmpeg 命令表，而是固定 `probe → edit → check → verify` 工作流，并提供 28 个实际工具，覆盖裁剪、拼接、静音移除、字幕、卡拉 OK、HDR→SDR、LUT、音频清理、同步漂移、多机位、响度和交付检查。
- **适合怎么用**：作为现有 AI Video Factory / Codex Native Video Workspace 的底层确定性媒体执行层；ComfyUI 负责生成，Codex 负责计划，ffmpeg-skill 负责本地剪辑/转码/QC，REAPER 继续承担精细音频后期。
- **本地部署/测试成本**：低～中。已有 FFmpeg 时主要增加 Python/Skill/MCP 配置，无云端、无 API Key。
- **当前状态**：**TRY**
- **下一步建议**：拿同一段 2–5 分钟素材，要求 Codex 完成“探测→裁剪→字幕→响度→导出→验证”，与现有 Kinocut/OpenChatCut 的后处理流程比较工具调用数、成功率和返工次数。
- **收藏库联动**：**已收藏 / 值得跟进**

## 2. luckyjackluo/cairn

GitHub: https://github.com/luckyjackluo/cairn

- **一句话用途**：给 Codex 一个完全本地的文件整理、标签、文档导入和语义检索工作区。
- **为什么值得看**：它把文件系统作为 source of truth，不要求云账户；MCP 提供约 26 个文件组织工具，可处理 list/read/search/grep/edit/move/tag，并可导入 DOCX/PDF/PPTX/XLSX/Markdown。默认词法检索无需模型，embedding 为可选项并能接 Ollama/LM Studio 等本地兼容接口。
- **适合怎么用**：不是替代 gno，而是测试“知识检索”之外的文件治理层：让 Codex 整理项目资料目录、统一标签、移动归档文件，再由 gno/其他检索工具承担更成熟的知识查询。
- **本地部署/测试成本**：低。Python/uvx 路线，一条 MCP 命令即可接 Codex；首次应只指向资料副本，因为它具备移动、重命名和编辑能力。
- **当前状态**：**REVIEW**
- **下一步建议**：复制一个杂乱的测试资料夹，验证自动分类、标签、Office/PDF 导入和回滚可控性；不要直接对正式资料目录开放写权限。
- **收藏库联动**：**已收藏 / 值得跟进**

## 今日结论

优先顺序：**ffmpeg-skill → Cairn → mcp-power-automate → GPTkms**。

今天真正值得动手的是 `ffmpeg-skill`：它与已有 FFmpeg、AI 视频、OpenChatCut、Kinocut、ComfyUI、REAPER 链路的结合最直接，而且可以用确定性的媒体任务快速做 A/B。其余三个更适合架构研究，避免继续无目的堆 MCP。

## 今日新增 Idea

### P0 — Deterministic Media Execution Layer

`Codex / video skills → ffmpeg-skill → Reaper-MCP / OpenChatCut → delivery QA`

把“生成式视频能力”和“确定性媒体处理”拆开。AI 负责脚本、镜头决策和生成素材；FFmpeg Skill 负责可重复的裁剪、字幕、转码、响度、同步和交付检查。目标是减少视频流水线里 Agent 临时拼 FFmpeg 命令导致的错误。

### P1 — Agent File Governance Sandbox

`Cairn → gno / MarkItDown / Codex`

建立一个只针对资料副本的文件治理沙箱：Codex 先通过 Cairn 整理、标签和归档，再进入现有文档预处理与知识检索层。验证稳定后才考虑扩大到真实工作目录。
